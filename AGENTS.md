# AGENTS.md

This document provides an overview of the project structure for developers and AI agents working on this codebase.

## Project Overview

**DonutSMP Central Reserve Board** — an authoritative economic dashboard for the Sovereign Standard [SOV] token, a custom in-game economy token for the DonutSMP Minecraft server. Players mint and redeem SOV against a faction reserve, submit order tickets, and watch trades settle on a live public ledger. A private admin console lets operators settle orders, promote verified holders, and adjust the global token value.

### Tech Stack

## Key Concepts

### Data Model (`db/schema.ts`)

- **`orders`** — one row per order ticket: `hash` (unique tracking ID), `ign`, `orderType` (`Buy`/`Sell`), `quantity`, `amount` (precomputed dollar value), `settled` (bool), `createdAt`.
- **`settings`** — simple key/value store. Currently holds `token_value` (the globally adjustable in-game token value). New settings should be added as new rows.

### Server Functions (`src/server/orders.functions.ts`)

All database access happens through TanStack Start server functions (type-safe RPC). These are safe to import from the route component:

- `getStats()` — circulating supply, token value, total wealth protected.
- `getOrders()` — every order row, newest first (used by both the public queue and the admin console).
- `getLeaderboard()` — aggregated verified-holder rankings derived from settled orders.
- `createOrder()` — validates IGN/orderType/quantity with Zod, generates a unique `#SOV-XXXX-X` hash, inserts an unsettled row.
- `settleOrder()` — marks an order settled; the leaderboard and stats recompute automatically from settled rows.
- `updateTokenValue()` — upserts the `token_value` setting and returns refreshed stats.
- `getTokenValue()` — reads the current global token value (defaults to the $150,000 floor).

Fixed economic constants: `BUY_PRICE = $200,000`, `FLOOR_PRICE = $150,000`.

### Component Architecture (`src/routes/index.tsx`)

The dashboard is a single route (`/`) composed of focused sections, all defined in `index.tsx`:

- `Header` — sticky glass header with logo placeholder, title, pulsing status badge, nav links.
- `Hero` — headline + tagline.
- `StatsBanner` / `GlassStatCard` — three glassmorphism stat panels (gold figures).
- `LiquidityInterface` — Acquisition Desk + Redemption Treasury columns.
- `OrderTicket` — the order form (IGN, order type, quantity) with live value preview.
- `TrackingQueue` — live public order table with orange "Awaiting" / green "Settled" badges.
- `Leaderboard` — verified-holder registry; shows a launch placeholder until the first order settles.
- `AdminConsole` — mirrored queue with neon-green settle buttons + global token-value field.
- `LegalFooter` — compliance disclaimer.

State is held in the `Home` component (`stats`, `orders`, `leaderboard`) and refreshed via `refreshAll()` after every mutation.

### Styling (`src/styles.css`)

Custom utility classes power the theme (defined as plain CSS alongside the Tailwind import):

- `.sov-glass` — glassmorphism panel background.
- `.sov-gold` — gold gradient text for high-value figures.
- `.sov-cyan-glow` / `.sov-cyan-border` / `.sov-cyan-btn` — frost-blue accents and primary buttons.
- `.sov-awaiting` / `.sov-settled` / `.sov-verified` — orange, green, and lime status badges with glows.
- `.sov-admin-btn` — neon-green settle button.
- `.sov-pulse` — pulsing animation for status dots.
- `.sov-row-in` — slide-in animation for new table rows.

Fonts: Inter (body) + Plus Jakarta Sans (headlines), loaded via Google Fonts in `styles.css` and preconnected in `__root.tsx`.

## Database Migrations

- Schema changes require a migration. After editing `db/schema.ts`, run:
  ```bash
  npx drizzle-kit generate --name <descriptive_snake_case_name>
  ```
- Migrations are applied automatically by Netlify during deploys — never run `drizzle-kit migrate` or execute migration SQL directly.
- The `@beta` dist-tag is required for `drizzle-orm` and `drizzle-kit` (the Netlify Database adapter only ships on the beta line).

## Conventions

### Naming
- Components: PascalCase
- Server functions: camelCase
- Routes: kebab-case files
- Server function files use the `.functions.ts` suffix

### TypeScript
- Strict mode enabled
- Import paths use `@/` alias (or relative `.js` extensions for server-only db imports)
- Zod for runtime validation in server function `inputValidator(...)`

### Server Functions
- Use `createServerFn({ method })` with `.inputValidator(...)` (not `.validator(...)`).
- All database access goes through server functions — never import `db` directly into client/route components.
